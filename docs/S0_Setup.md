## Implemented architecture

One root app package. Two thin Expo Router routes provide contents and a chapter reader. Plain React context exposes initialized storage and persisted reading preferences; no global state library, ORM or generic source layer.

`src/domain/` defines numeric-string fixture thread/post identity and content/locator types. The synthetic namespace is deliberately `fixture`, never a live SpaceBattles story. Titles and chapter ordering do not determine identity.

`src/fixtures/story.ts` supplies the original three-chapter story. Chapter 1 is long prose with headings, emphasis, quotes, list, scene break, table, nested details/summary, a deliberate HTTPS Example Domain link, a bundled PNG, and hostile source script/handler/frame/style/image fixtures. No forum content was fetched.

`src/content/` runs `htmlparser2@12.0.0` and a recursive explicit tag/attribute allowlist serializer. It removes source scripts, forms, frames, SVG, arbitrary CSS, handlers, remote images and active URLs. IDs and link handles are generated by the app. Canonical HTML gets SHA-256 over sanitizer version + HTML using Expo Crypto. Numbered block IDs are stable within the exact content hash, not across edits. There is no browser DOM emulation or Node polyfill stack in the app.

`src/storage/` has one versioned SQL migration, foreign keys, parameterized writes and a serialized queue around Expo SQLite's **exclusive** transaction API. Expo starts those transactions on a new connection, so a `foreign_key_check` guard inside the callback rejects invalid references before commit even when that connection's foreign-key switch defaults off. Setting `foreign_keys` after BEGIN would be ineffective ([SQLite PRAGMA behavior](https://www.sqlite.org/pragma.html#pragma_foreign_keys)). Host tests model that new connection explicitly. Tables are stories, chapters, reading_positions, assets and settings. Full v0 threadmark/read-state/download tables are not needed by this slice. Conflict-safe fixture insertion never replaces existing chapters or locators. Current HTML/hash/sanitizer version/block IDs/link map commit together. Contents queries only metadata; the reader reads only the active body.

The original `assets/harbor.png` is a 480×240, 2,024-byte raster generated for this fixture. The app verifies its PNG signature/header/dimensions and exact SHA-256, stages a generated immutable document file, then commits a relative path. Limits are 2 MB and 2,048 pixels per dimension. A missing/corrupt asset can be replaced with a fresh validated file; text survives image failure. A failed DB commit can leave an unreferenced file. Native crash timing is not yet proven. Old asset references are never overwritten in place.

`src/reader/` regenerates one local HTML file in a generated per-opening rendering directory. SQLite remains canonical. WebView read access is restricted to that directory on iOS; file-to-network access, mixed content, cookies and DOM storage are disabled. CSP permits the app's nonce-bearing script/style and local images only. Every navigation goes through an exact current-file check; source anchors are prevented, and validated deliberate clicks are sent through the bridge to the system browser. `originWhitelist` is not treated as a resource firewall.

The bundled trusted bridge validates native messages by session, chapter, hash, block, offsets and shape. It captures the block at the reading line, CSS-pixel offset, progression and expanded spoiler IDs. The native side debounces SQL writes by 300 ms after the bridge's 150 ms quiet period. Navigation/backgrounding request a bridge flush and wait where possible; already received writes are awaited. An abrupt kill restores the last committed locator.

Initial render waits for local image completion and restores before sending ready. Reflow captures the current block, flushes real reading movement, pauses reporting, applies typography, opens necessary spoiler ancestors and restores. Programmatic loading/reflow scrolls are never saved; another trusted reading gesture is required. Hash changes or missing blocks use progression. Cross-edit text matching is excluded.

Setup failures were diagnosed and corrected: the system npm global-prefix directory was missing; PowerShell blocked portable npm `.ps1` launchers; scaffolding the nonempty root rejected `.tools`; npm initially chose incompatible optional Router peers; initial Jest transforms missed Expo subpackages. A temporary scaffold, `.cmd` launchers, explicit SDK peer pins and the corrected Jest transform allowlist resolved these. No `--force`, `--legacy-peer-deps`, test weakening or source requests were used.

Validation: strict TypeScript and lint pass; **39 tests across 7 suites** pass; Expo dependency compatibility passes; Expo Doctor passes **21/21**; iOS Hermes export includes `harbor.png`. A final clean `npm ci` verifies the committed dependency graph. Metro's offline startup produced an Expo Go LAN QR code successfully, then was stopped; the restricted sandbox denied DevTools' external cache directory and Expo used its fallback. Node reports `node:sqlite` as experimental; the tests use its actual SQLite engine, not a repository mock.

The host SQLite integration covers fresh migration, repeated seed, close/reopen, metadata preservation, locator/preferences persistence, foreign keys, write serialization and injected pre-commit failure/rollback. Bridge tests execute the actual app script with a test DOM and emulated geometry; they do not establish real WKWebView layout. The native unit preset mocks native modules. CI runs a clean install, typecheck, lint, fixture tests, compatibility check and iOS export; the remote workflow has not been run here.

`npm audit` reports **60 findings (50 high, 10 moderate)** in the SDK/tooling dependency tree, including propagated braces/micromatch, node-forge, uuid and Router query decoding advisories. Its suggested framework changes include a downgrade to Expo 44 or moving to SDK 58; those do not satisfy the selected stable SDK. No forced upgrade or untested overrides were applied. This is an unresolved dependency limitation, separate from sanitizer fixture results.
